# 안심 지킴이

프로젝트를 시작하기 전에 [docs/SETUP.md](docs/SETUP.md)를 먼저 읽으세요.

## 프로젝트 개요
- 한 줄 소개: 어르신에게 오는 스미싱(문자 사기)을 받는 순간 감지해 막고, QR 코드와 받은 문자를 학습된 AI가 검사하는 스미싱 차단 웹앱(PWA) (개발 중)
- 누구를 위한 앱인가: 스마트폰 사기 문자에 취약한 어르신과, 어르신을 돌보는 가족(보호자)
- 어떤 상황에서 쓰는가: 택배·가족 사칭·정부 지원금 같은 의심 문자나 카톡을 받았을 때, 전단지·우편물의 QR 코드를 찍기 전에, 받은 문자가 사기인지 확인하고 싶을 때

## 주요 기능

| 1. 실시간 문자 인식·감지·차단 — 가상 휴대폰을 쓰다가 문자·카톡이 도착하는 순간 학습 AI가 채점해 위험도별 경고 팝업을 띄우고, 문자 속 위험한 링크를 누르면 사이트를 막고 앱 설치 화면을 가림. 받은 문자는 말풍선을 눌러 복사할 수 있음. 감지 결과는 검사 기록으로 저장되고 "사기 맞아요/아니에요" 정답 알려 주기·메모 고치기·지우기 | `/check` 실시간 감지 탭 (`src/app/(app)/check/demo-phone.tsx`), 가상 휴대폰 `src/lib/phone/engine.ts` | Server Action `createDemoScan`·`updateScanVerdict`·`updateScanMemo`·`deleteScan` (`src/app/(app)/scan-actions.ts`), 채점 `src/lib/scan/analyze.ts` |
| 2. QR 감지 — QR 코드를 찍으면 주소를 열지 않고 먼저 검사(단축 주소·수상한 도메인·http·앱 설치 파일 등)해 결과 창으로 알리고 기록으로 저장. 찍는 방법은 체험용 QR 찍기(카메라처럼 비추다 인식, 위험→주의→안전 차례), 카메라로 진짜 QR 찍기, 직접 입력. 결과 창은 위험·주의·안전과 위험도·판단 이유를 보여 주고, **위험**이면 "🔒 링크 접속을 차단했어요", **주의**면 바로 열지 않고 [그래도 열기] → "정말 여시겠어요?" 한 번 더 확인한 뒤 열기, **안전**한 https 주소만 [이 주소 열기]. 메모 고치기·지우기 | `/check` QR 검사 탭 (`src/app/(app)/check/QrScanner.tsx`), 결과 창 `src/components/VerdictSheet.tsx`, 체험용 QR 그림 `src/components/DemoQrImage.tsx`·`src/lib/scan/demo-qr.ts` | Server Action `createQrScan`(판별·저장 후 위험도·이유를 돌려줌)·`updateScanMemo`·`deleteScan` (`src/app/(app)/scan-actions.ts`), 판별 `src/lib/scan/rules.ts`, 체험용 QR 8개(가짜 주소) `src/app/(app)/check/samples.ts` |

- 현재 상태: 화면·서버 처리·DB 모델을 만들고 타입 검사·린트·빌드를 확인했습니다. Supabase(서울)에 연결해 배포 주소에서 가입·로그인·검사 저장·새로고침 유지·로그아웃 차단·다른 계정 자료 차단을 확인했습니다.
- 로그인(이메일·비밀번호, Supabase Auth)해야 위 화면을 쓸 수 있고, 내 기록은 나만 보입니다(모든 서버 처리가 로그인 확인 → 입력 검증 → 내 자료인지 확인).
- 로그인 화면 `/login` (`src/app/login/`): 로그인/가입하기 탭, 입력 예시(예: hong@naver.com), 👁 비밀번호 보기, 가입할 때 "비밀번호 한 번 더"(서버에서도 `signUpSchema`로 다시 비교), 잘못 넣은 칸은 빨간 테두리와 칸 아래 안내, 로그인에 실패하면 [가입하기] 안내. 로그인·가입하면 바로 문자 지킴이의 가상 휴대폰(`/check?tab=demo`)으로 이동
- 웹앱은 휴대폰의 실제 문자함을 읽을 수 없어서, 1번은 체험용 문자가 가상 휴대폰에 도착하는 상황으로 보여 줍니다. 실제로 받은 문자는 3번(붙여 넣기·[공유])으로 검사합니다.

더 만든 기능:
- 보호자·연락처 관리 — 가족·보호자 추가·고치기·지우기, 바로 전화 걸기 (`/contacts`)
- 홈 요약 — 세 가지 검사 기록(전체·위험·QR·정답 알려 준 기록)을 모아 보여 주는 화면 (`/home`)
- 시뮬레이션 — 가상 휴대폰에 설치된 앱으로 세 기능을 체험하는 미리보기 페이지. `npm run demo:build`로 `demo/dist/simulation.html`을 만든다 (`demo/`)
  - 로그인: 실제 앱과 같은 로그인·가입 화면으로 시작하고(입력 규칙도 실제 앱의 `authSchema`·`signUpSchema`를 그대로 씀), 로그인하면 가상 휴대폰으로 넘어감. 조작판 위에 로그인한 이메일과 [로그아웃]. 시뮬레이션이라 계정을 실제로 만들지 않고 아무것도 저장하지 않음(형식이 맞으면 로그인되고, 실패 장면은 비밀번호 `wrongpass`)
  - 경고 팝업의 닫기 버튼은 앱 결과 창과 같은 [확인했어요]로 통일
  - QR: 가상 휴대폰의 **카메라 앱**을 열면 실제 카메라처럼 검은 화면·격자에 체험용 QR이 비춰지고, **셔터를 누르면** 모서리 틀이 QR 크기에 맞게 조여지며 판독. 위험·주의는 문자 판독과 같은 경고 팝업(위험도, 차단 문구·사이트 이름·판단 이유를 한 색상 박스에)과 [링크 열기] — 위험은 막아 둔 주소라 "위험한 사이트를 막았어요" 화면, 주의는 "정말 여시겠어요?" 확인 창. 정상은 팝업 없이 초록 "안전한 QR" 표시. 카메라 앱에서는 왼쪽 조작판이 [QR 코드 받기]로 바뀌어 비출 QR을 고를 수 있음. 안심 지킴이 앱 안 QR 검사도 같은 연출·결과 창 (`demo/guardian-app.ts`, 카메라 QR 모드 `src/lib/phone/engine.ts`)
- PWA — 홈 화면에 설치, 문자 앱에서 [공유]로 바로 검사 (`src/app/manifest.ts`, `public/sw.js`)

## 기술 스택
- 프론트엔드: Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, Zod(입력 규칙), 브라우저 내장 QR 인식(BarcodeDetector)
- 백엔드: Next.js Server Action, Prisma 7 (`@prisma/adapter-pg`), Supabase Auth (`@supabase/ssr`) 로그인, `src/proxy.ts`에서 로그인 세션 갱신·보호된 화면 접근 차단
- 데이터(어디에, 무엇을): Supabase PostgreSQL (`prisma/schema.prisma`) — `users`(회원, Supabase Auth 사용자 id), `scan_records`(메시지·QR 검사 기록: 내용·위험도·이유·메모), `contacts`(보호자·연락처)

## 실행 방법
<!-- 처음 보는 사람이 그대로 따라 할 수 있게 쓴다. 시작 저장소 그대로라면: npm install → npm run dev → 브라우저에서 http://localhost:3000 -->
1. Node.js 24를 설치하고 저장소를 내려받은 뒤 `npm install`을 실행합니다.
2. `.env.example`을 `.env`로 복사하고 Supabase 값을 넣습니다. 자세한 방법은 [docs/SUPABASE_SETUP.md](docs/SUPABASE_SETUP.md)를 참고합니다.
   - `DATABASE_URL`(Transaction pooler, 6543), `DIRECT_URL`(Session pooler, 5432)
   - `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`(공개 키만 — secret 키는 넣지 않음)
   - Supabase → Authentication → Sign In / Providers에서 이메일 확인(Confirm email)을 끕니다(가입 후 바로 로그인).
   - DB 표 만들기: `npm run db:migrate:deploy` (표 3개와 RLS 보안 설정이 `prisma/migrations/`에 있습니다). 연결 점검은 `npm run db:check`.
3. `npm run dev`를 실행하고 브라우저에서 http://localhost:3000 을 엽니다.

배포 주소: https://team-spk.vercel.app (Vercel 서울 `icn1` — Supabase DB도 서울 `ap-northeast-2`. 설정은 `vercel.json`)

QR 모양 그리기를 실제 앱과 시뮬레이션이 함께 쓰도록 공통화(`src/lib/scan/demo-qr.ts`)

  - 사람: 아이디는 이메일을 유지하기로 정하고, 로그인하면 바로 휴대폰 화면으로 가게 하고, 시뮬레이션에서도 로그인 화면과 휴대폰 화면이 이어지게 하라고 정함. 시뮬레이션에서 틀린 비밀번호로도 로그인되는 점을 발견
  - 사람: 시뮬레이션을 직접 써 보며 QR 연출을 다듬음 — 고르기 줄을 없애고 셔터로 판독, 모서리 틀을 QR 크기에 맞추기, 주의·위험은 주소 색이 아니라 팝업으로, 위험은 링크 차단·주의는 한 번 더 물은 뒤 열기, 이유를 색상 박스 안에, 결과 창에 [링크 열기]. 주의 단계가 잘 안 보이는 문제를 찾아 체험용 QR 구성을 바꾸게 함
  - 사람: 심사 기준(주요 기능 1·2·3 채점)을 확인한 뒤 서비스 핵심을 스미싱 차단으로 좁히고 주요 기능 3개(실시간 감지·차단, QR 감지, 붙여 넣기 AI 판단)를 정함

  - 사람: 심사 기준 확인 범위(세부 기준까지)를 다시 확인하도록 요청하고, 지침으로 남길 내용과 README 작성 방식을 정함. 운영진이 강조한 DB·API 보안 사고 주의 사항을 전달해 지침에 반영하게 함. 서비스 주제(어르신 스미싱 방지)를 정하고, 안드로이드 앱 대신 웹앱을 기본으로 만들라는 운영진 안내를 확인해 방향을 정함
- 결과를 확인한 방법: 대회 사이트 화면의 심사 기준과 정리한 문서를 비교, `npx prettier --check`로 문서 서식 확인, GitHub 저장소에서 커밋 반영 확인. 뼈대는 `npm run typecheck`·`npm run lint`·`npm run db:validate`·`npm run build` 통과, 예시 사기 문자 5개·QR 5개로 판별 결과 확인, 로그아웃 상태로 `/check`를 열면 `/login`으로 가는지 확인. 학습 AI 채점은 학습 데이터에 없는 예시 문자 7개(사기 4·정상 3)로 결과가 맞는지 확인, 합친 코드는 `tsc`·`eslint`·`next build` 통과. QR 감지는 체험용 QR 8개의 판독 결과(위험 3·주의 3·안전 2)를 판별 코드로 직접 계산해 확인하고, 시뮬레이션은 헤드리스 크롬으로 카메라 열기 → 셔터 → 경고 팝업·차단 문구·확인 창·[링크 열기]를 자동으로 눌러 화면을 찍어 확인, 바꿀 때마다 `npm run typecheck`·`eslint`·`npm run build`·`npm run demo:build` 통과. 로그인 화면은 앱을 실제로 띄워 휴대폰 폭(390px)과 넓은 화면을 찍어 확인하고, 크롬을 원격 조종해 [가입하기] 탭에서 서로 다른 비밀번호로 가입을 눌러 서버가 "비밀번호가 서로 달라요"로 막는지 확인. 배포 주소에서 새 로그인 화면이 뜨는지와 로그아웃 상태로 `/check`를 열면 `/login`으로 보내지는지(307) 확인. 시뮬레이션은 로그인하면 휴대폰 화면으로 넘어가는지 원격 조종으로 확인
